# 工作日志：将 PlayerSeekService 合并至 PlayerService

## 一、目标

上一轮需求「配置中增加后退 / 快进时长配置」中，为承载快进 / 快退目标时间的纯计算逻辑，单独新建了 `src/main/services/PlayerSeekService.js`。本轮目标：将该文件中的全部内容（常量、规整工具函数、`calculateSeekTarget` 方法）合并进既有的 `src/main/services/PlayerService.js`，消除独立的 `PlayerSeekService`，使播放器相关服务收归单一文件，降低维护与认知成本。

约束（沿用 Must Do）：

- 合并后所有相关代码仍需有单元测试覆盖并执行通过。
- 代码满足 CleanCode：命名清晰、注释详细。
- 整理中文工作日志，写入 `worklog/` 目录，文件名为时间戳 `-worklog.md`。

## 二、涉及文件

| 类别 | 文件 | 改动 |
| --- | --- | --- |
| 服务层 | `src/main/services/PlayerService.js` | 合并 seek 常量、`normalizeSeekStep` / `normalizeTime` 工具函数与 `calculateSeekTarget` 方法；模块导出常量；更新文件头注释 |
| 服务层 | `src/main/services/PlayerSeekService.js` | **删除** |
| 预加载 | `preload.js` | `require` 由 `PlayerSeekService` 改为 `PlayerService`；实例名 `playerSeekService` → `playerService`；注释同步 |

| 测试 | `test/svc/PlayerService.test.js` | 新增 `calculateSeekTarget - 快进 / 快退计算` describe，并入原 `PlayerSeekService.test.js` 的 20 条 SVC-SEEK 用例，常量引用改为 `PlayerService.*` |
| 测试 | `test/svc/PlayerSeekService.test.js` | **删除** |

## 三、工作过程

### 1. 影响面分析

全局检索 `PlayerSeekService`，确认引用点：

- `preload.js`：`require` + 实例化 + `contextBridge` 暴露的 `calculateSeekTarget` 包装 + 一处注释。
- `src/renderer/js/player.js`：仅两处注释提及，无实际 `require`（渲染层经 `window.electronAPI` 调用）。
- `test/svc/PlayerSeekService.test.js`：20 条用例，直接 `require` 并断言导出常量。
- `worklog/20260720004412-worklog.md`：上一轮工作日志中的历史描述（属点-in-time 记录，保留不动，由本日志补充说明后续合并）。

代码层无其他依赖，合并可控。

### 2. 合并设计

`PlayerSeekService` 原为无状态纯计算服务，合并进 `PlayerService`（有状态的播放列表 / 字幕服务）时遵循「保持原有行为与可测性不变」原则：

- **常量** `DEFAULT_SEEK_STEP` / `DIRECTION_BACKWARD` / `DIRECTION_FORWARD` 与 **工具函数** `normalizeSeekStep` / `normalizeTime`：作为模块级私有定义置于 `PlayerService.js` 顶部 `require` 之后、`class PlayerService` 之前，附「快进 / 快退计算」分段注释与 JSDoc，保持其纯函数、无副作用特性，与原文件完全一致。
- **方法** `calculateSeekTarget`：作为 `PlayerService` 类的实例方法，置于类末尾（`loadSubtitle` 之后），逻辑、参数、边界规则与注释逐字搬迁，未做任何行为修改。
- **导出**：原 `PlayerSeekService` 通过 `module.exports.DEFAULT_SEEK_STEP = ...` 等挂载常量；合并后在 `module.exports = PlayerService;` 之后以相同方式挂载，保证 `PlayerService.DEFAULT_SEEK_STEP` 等访问路径不变，测试与潜在外部引用零破坏。
- `PlayerService` 构造函数本身仅初始化 `currentPlaylist` / `currentIndex`，在 `preload.js` 中实例化以调用 `calculateSeekTarget` 无副作用、无额外开销；`preload` 具备 Node 访问能力，`require` 含 `path` / `fs` 的 `PlayerService` 不存在问题。

### 3. 引用更新

- `preload.js`：`require('./src/main/services/PlayerSeekService')` → `require('./src/main/services/PlayerService')`；实例 `playerSeekService` → `playerService`；`calculateSeekTarget` 包装内的调用对象同步替换；注释由「复用主进程 PlayerSeekService」改为「PlayerService」。
- `player.js`：`ArrowLeft` / `ArrowRight` 两处注释 `PlayerSeekService` → `PlayerService`，调用代码不变（仍为 `window.electronAPI.calculateSeekTarget(...)`）。

### 4. 测试合并

将 `PlayerSeekService.test.js` 的 20 条用例迁入 `PlayerService.test.js`，新增 `describe('calculateSeekTarget - 快进 / 快退计算')`，下分「快进 (forward)」「快退 (backward)」「自定义步长」「步长规整」「边界与异常输入」「导出常量」六个子 describe，结构与原文件一致。调整点：

- 复用 `PlayerService.test.js` 顶层 `beforeEach` 已创建的 `playerService` 实例，取代原 `service = new PlayerSeekService()`。
- 常量断言由 `PlayerSeekService.DEFAULT_SEEK_STEP` 等改为 `PlayerService.DEFAULT_SEEK_STEP` 等。
- 用例 ID（SVC-SEEK-001 ~ 020）与断言值完全保留，确保覆盖范围不缩水。

随后删除 `test/svc/PlayerSeekService.test.js` 与 `src/main/services/PlayerSeekService.js`。

### 5. 验证

- 语法检查：`node --check` 通过 `PlayerService.js`、`preload.js`、`player.js`、`PlayerService.test.js`。
- 模块冒烟：`node -e` 实例化 `PlayerService`，`calculateSeekTarget(100,300,10,'forward')` → `110`、`calculateSeekTarget(5,300,10,'backward')` → `0`；导出常量 `DEFAULT_SEEK_STEP=10`、`DIRECTION_FORWARD='forward'`、`DIRECTION_BACKWARD='backward'` 均正常。
- 单元测试：`npx jest test/svc/PlayerService.test.js` → **56 passed**（原 36 条 + 合并入的 20 条 SVC-SEEK 全部通过）。
- 全局检索 `PlayerSeekService`：代码与测试中已无任何引用，仅上一轮历史工作日志中作为点-in-time 记录保留。

## 四、工作结果

1. **合并完成**：`PlayerSeekService.js` 的常量、工具函数与 `calculateSeekTarget` 方法已全部并入 `PlayerService.js`，独立文件与服务已删除，播放器相关服务收归单一文件。
2. **零行为变更**：计算逻辑、边界规则、默认值回退、导出常量访问路径均与合并前一致；`preload.js` / `player.js` 的运行时行为不变（仅替换底层实例与注释）。
3. **测试全绿**：合并后的 `PlayerService.test.js` 共 56 条用例全部通过，原 20 条 SVC-SEEK 用例覆盖完整保留。
4. **CleanCode**：合并代码沿用详细中文 JSDoc 与分段注释，模块级常量 / 工具函数与类方法分层清晰，命名不变，与既有 `PlayerService` 风格一致。
