# 工作日志：配置中增加音量步长配置（Volume Step）

## 一、目标

为 video-deck（Electron 电影管理程序）的播放器增加「音量步长（Volume Step）」可配置项，使用户可在「配置」模态窗中自定义方向键 `ArrowUp` / `ArrowDown` 调节音量时的单次变化量，替代播放器中硬编码的 `5`。

具体需求：

1. 在「配置」（setting-modal）模态窗的「播放器配置」Tab（tab-player-settings）「声音配置」分区下，新增「音量步长（Volume Step）」配置。
2. 「音量步长」配置默认值 `5`，采用整数输入，支持上下数字调整（spinner 与方向键）。
3. 将 `src/renderer/js/player.js` 中 `ArrowUp` / `ArrowDown` 分支 `Math.min(100, parseInt(elements.volumeBar.value) + 5)` 与 `Math.max(0, parseInt(elements.volumeBar.value) - 5)` 中的硬编码 `5`，替换为从「音量步长」配置中读取的值。

约束（Must Do）：

- 所有新增代码均需生成单元测试用例，并完成单元测试用例执行。
- 所有代码需满足 CleanCode 要求：变量 / 方法命名清晰，注释详细。
- 整理中文工作日志，写入 `worklog/` 目录，文件名为时间戳 `-worklog.md`。

## 二、设计决策

本需求与上一版「快进 / 快退间隔（Seek Step）」功能同构，故沿用其既有的、经实测验证的架构模式，保证风格一致、可维护。

关键约束分析：

- 播放器窗口 `nodeIntegration: false`、`contextIsolation: true`，渲染层无法直接 `require` 主进程模块，只能使用 `preload.js` 经 `contextBridge` 暴露的 `window.electronAPI`。
- Jest 配置 `testEnvironment: 'node'`、`testMatch: ['**/test/svc/**/*.test.js']`，渲染层 JS（`player.js` / `main.js`）不在测试范围内。需求要求「所有新增代码均需生成单元测试」，因此音量目标值的计算逻辑必须落在 Node 可加载的服务模块中才可被单元测试覆盖。
- 既有音量 / 字幕 / 快进间隔的模式是：渲染层初始化时通过 `window.electronAPI.getSettings()` 异步读取配置并缓存，键盘交互则使用缓存值做同步计算，保证方向键的即时响应。

基于此，采用「纯计算服务 + preload 同步暴露」方案：

- 在 `PlayerService` 中新增纯函数 `calculateVolumeTarget(currentVolume, volumeStep, direction)`，承载「按步长与方向计算目标音量、并做 [0, 100] 边界裁剪」的逻辑。纯函数、无副作用、不依赖 Electron / DOM，可在 Node 环境完整单元测试。
- `preload.js` 通过 `contextBridge` 同步暴露 `calculateVolumeTarget`（复用 `PlayerService` 实例）。对原始类型参数为同步调用，无 IPC 往返延迟，既保持方向键调节音量的即时响应，又复用同一份被测试覆盖的计算逻辑，避免在渲染层重复实现裁剪公式。

> 备选方案对比：① 在渲染层内联裁剪公式并镜像一份到服务层供测试——存在重复实现，违反 CleanCode 单一来源原则；② 通过 `ipcMain.handle` 提供 IPC——方向键每次触发都有 IPC 往返，影响即时性，且与既有音量（纯客户端）模式不一致。最终选用「纯服务 + preload 同步暴露」兼顾可测、无重复、即时。

> 说明：上一版「快进 / 快退间隔」工作日志中将计算服务描述为独立的 `PlayerSeekService.js`，但实际代码中该逻辑位于 `PlayerService.js` 的 `calculateSeekTarget` 方法。本日志以代码实际状态为准，将音量计算同样落于 `PlayerService`，与既有 seek 计算并列，结构更内聚。

## 四、工作过程

### 1. 现状分析

阅读 `index.html`（播放器配置 Tab 的「声音配置」分区结构）、`player.js`（键盘快捷键 `ArrowUp` / `ArrowDown` 与 `applyVolumeSettings` / `applySeekStepSettings` 既有的「init 时读配置并应用」模式）、`main.js`（`loadSettings` 回显与 `saveSettingsHandler` 保存的配置读写）、`SettingsService` / `HardCodeService`（默认值与读写方法）、`PlayerService`（既有 `calculateSeekTarget` 纯计算模式）、`preload.js`（`contextBridge` 暴露的 API）。

关键发现：

- `player.js` 中 `ArrowUp` / `ArrowDown` 的 `+ 5` / `- 5` 即为硬编码音量步长，需求要求其改为可配置。
- 既有 `calculateSeekTarget` 已在 `PlayerService` 中以纯函数形式实现并经 preload 同步暴露，是音量计算的直接参照模板。
- 渲染层 JS 不在 Jest 测试范围，故计算逻辑必须下沉到服务层才可单元测试。
- 音量范围为固定 `[0, 100]`（不同于 seek 的 duration 可能未知），边界裁剪更简单：增大裁剪到 100、减小裁剪到 0，无需「Infinity 兜底」。

### 2. 服务层实现

**`PlayerService`**：

- 新增常量 `DEFAULT_VOLUME_STEP = 5`、`VOLUME_MIN = 0`、`VOLUME_MAX = 100`、`VOLUME_DIRECTION_UP = 'up'`、`VOLUME_DIRECTION_DOWN = 'down'`。
- `normalizeVolumeStep` / `normalizeVolume` 私有规整函数：非数字 / NaN / 非正数（步长）回退默认值，非数字 / NaN（音量）按 0 处理。
- `calculateVolumeTarget(currentVolume, volumeStep, direction)`：
  - 增大（`up`）：`Math.min(VOLUME_MAX, baseVolume + step)`，裁剪到上限 100。
  - 减小（`down`）：`Math.max(VOLUME_MIN, baseVolume - step)`，裁剪到下限 0。
  - 未知方向：返回当前音量，保持原位。
- 模块导出补充上述 5 个常量，供测试与调用方引用。

**`HardCodeService.getDefaultSettings()`**：在 `player` 节点新增 `volumeStep: 5`，作为全应用默认音量步长。

**`SettingsService`**：

- `getPlayerConfig()` 兜底默认值补充 `volumeStep: 5`。
- 新增 `getVolumeStep()`：读取 `settings.player.volumeStep`，非数字或非正数回退 `5`，保证调用方始终拿到有效步长。
- 新增 `setVolumeStep(step)`：写入 `settings.player.volumeStep` 并持久化。
- `setPlayerConfig` 既有实现对 `subtitle` 以外的顶层键（`volume` / `seekStep` / `volumeStep` 等）按整体写入且保留未提供字段，`volumeStep` 无需额外改造即可正确保存，无回归。

### 3. 预加载层实现

`preload.js` 在 `contextBridge.exposeInMainWorld('electronAPI', {...})` 中新增：

```js
// 播放器音量调节目标值计算（纯函数，同步调用，复用主进程 PlayerService）
calculateVolumeTarget: (currentVolume, volumeStep, direction) =>
    playerService.calculateVolumeTarget(currentVolume, volumeStep, direction),
```

同步纯函数，渲染层可直接 `elements.volumeBar.value = window.electronAPI.calculateVolumeTarget(...)`。

### 4. 渲染层 UI 与逻辑

**`index.html`**：在 `tab-player-settings` 的「声音配置」分区内、音量滑条之后插入「音量步长」输入：

```html
<div class="settings-item">
    <label>音量步长：</label>
    <input type="number" id="volume-step-setting" min="1" max="100" step="1" value="5" placeholder="5">
</div>
```

`type="number"` + `step="1"` + `min="1"` + `max="100"` 提供整数输入与上下数字调整（spinner 与方向键）。

**`main.js`**：

- 元素注册表新增 `volumeStepSetting: document.getElementById('volume-step-setting')`。
- `loadSettings()` 在音量回显之后，回显 `player.volumeStep`（非正数回退 5）。
- `saveSettingsHandler()` 在构造 `newSettings` 前校验输入：`parseInt` 后非正整数回退 5，再将 `volumeStep` 写入 `player` 节点，与 `volume` / `seekStep` 并列。

**`player.js`**：

- 新增模块级变量 `let currentVolumeStep = 5;`。
- 新增 `applyVolumeStepSettings()`：读取 `settings.player.volumeStep`，缓存到 `currentVolumeStep`（缺失 / 非正数回退 5）；初始化时与 `applySubtitleSettings` / `applyVolumeSettings` / `applySeekStepSettings` 一并 `await` 调用。
- 键盘 `ArrowUp` / `ArrowDown` 两分支替换为：

```js
case 'ArrowUp':
    // 音量增大：通过 PlayerService 计算目标音量，步长取自音量配置（currentVolumeStep）
    elements.volumeBar.value = window.electronAPI.calculateVolumeTarget(
        parseInt(elements.volumeBar.value), currentVolumeStep, 'up');
    elements.volumeBar.dispatchEvent(new Event('input'));
    break;
case 'ArrowDown':
    // 音量减小：通过 PlayerService 计算目标音量，步长取自音量配置（currentVolumeStep）
    elements.volumeBar.value = window.electronAPI.calculateVolumeTarget(
        parseInt(elements.volumeBar.value), currentVolumeStep, 'down');
    elements.volumeBar.dispatchEvent(new Event('input'));
    break;
```

**`config/settings.json`**：`player` 节点新增 `"volumeStep": 5`，使运行时配置文件自描述。
