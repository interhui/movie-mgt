## 1. 任务目标

在批量电影搜索功能中，将原有的串行搜索改为多线程并发搜索，提升搜索效率。

### 具体需求
1. 在 `batch-search-modal` 中点击"搜索"（`batch-search-start`）后进行电影搜索
2. 在 `BatchSearchService.js` 的 `batchSearchMovies` 方法中，对选择的电影采用多线程方式执行搜索
3. 线程数量默认为 5 个
4. 每个新增的后台业务代码必须生成单元测试，且测试必须执行通过
5. 代码满足 CleanCode 要求，保证整洁、可读

### 2.2 关键发现

**当前实现（串行模式）：**
- `batchSearchMovies` 使用 `for` 循环逐个 `await this.searchMovie(...)` 
- 每次搜索涉及 2 次 HTTP 请求（`searchMovie` + `getMovie`）
- N 部电影需要 N×2 次串行请求，效率低下

**调用链：**
```
batch-search-start (按钮点击)
  → startBatchSearch() [renderer/js/main.js:5182]
    → window.electronAPI.batchSearchMovies() [preload.js:222]
      → ipcMain.handle('batch-search-movies') [ipc-handlers.js:2102]
        → batchSearchService.batchSearchMovies() [BatchSearchService.js:165]
```

**进度回调机制：**
- IPC handler 通过 `webContents.send('batch-search-progress', progress)` 发送进度
- Renderer 通过 `updateBatchSearchProgress(progress)` 更新 UI
- 进度对象包含：`current`, `total`, `movieId`, `status`, `result`

### 2.3 方案设计

Node.js 是单线程的，但对于 I/O 密集型任务（HTTP API 调用），并发 Promise 执行等同于多线程效果。

**方案对比：**

| 方案 | 描述 | 优势 | 劣势 |
|------|------|------|------|
| **A. Worker Pool（推荐）** | 维护大小为5的 worker 池，从队列取任务执行 | 最高效，无空等 | 实现稍复杂 |
| B. 分块并发 | 电影分成每组5个，`Promise.all` 并发 | 实现简单 | 每组需等最慢的完成，有气泡 |

**选择方案A**，理由：性能最优，代码依然清晰可读。

### 3.2 实现详情

#### 3.2.1 BatchSearchService.js - batchSearchMovies 重写

**核心设计：Worker Pool 并发模式**

```javascript
async batchSearchMovies(movies, adapterType, progressCallback, concurrency = 5) {
    this.resetCancelled();

    const total = movies.length;
    const results = new Array(total);
    let completedCount = 0;
    let nextIndex = 0;

    // Worker 函数：从共享队列中取任务执行
    const searchOne = async () => {
        while (nextIndex < total && !this.cancelled) {
            const index = nextIndex++;       // 原子取号
            const movie = movies[index];

            // 搜索前进度
            if (progressCallback) { ... }

            const searchResult = await this.searchMovie(...);

            results[index] = { movie, searchResult };  // 按原始索引存储
            completedCount++;

            // 搜索完成进度
            if (progressCallback) { ... }
        }
    };

    // 启动 min(concurrency, total) 个 worker
    const workerCount = Math.min(concurrency, total);
    const workers = [];
    for (let i = 0; i < workerCount; i++) {
        workers.push(searchOne());
    }

    await Promise.all(workers);
    return results.filter(r => r !== undefined);
}
```

**关键设计决策：**

1. **共享队列 + 原子取号**：多个 worker 共享 `nextIndex` 变量，通过 `nextIndex++` 原子操作取任务，避免锁竞争
2. **结果按原始索引存储**：`results[index] = ...` 确保结果顺序与输入一致，不受完成顺序影响
3. **并发数自适应**：`Math.min(concurrency, total)` 避免创建多余 worker
4. **取消机制兼容**：worker 循环条件检查 `this.cancelled`，取消后立即停止取新任务
5. **进度回调兼容**：保持与原接口完全一致的 progress 对象格式
6. **向后兼容**：新增 `concurrency` 参数有默认值 5，现有调用无需修改
